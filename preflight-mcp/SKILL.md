# Preflight MCP — MCP 起手健康检查

在正式调用 MCP 执行任务之前，先用最小成本确认：**工具活着、目标存在、结果可信**。

## 使用时机

在以下场景优先执行本 skill：

- 用户要求连接某个 MCP 服务
- 用户要从设计、知识库、第三方平台或远端系统拉取内容
- 用户要通过 MCP 导出组件、读取页面、写入文档、抓取资源
- 最近上下文里已经出现过 MCP 断连、认证失败、405/401/403/5xx、目标文件不存在等问题

## 默认假设

- 本 skill **只做检查，不做修复**
- 优先使用目标 MCP 的**最轻量读取接口**做探测
- 只检查和当前任务直接相关的 MCP，不做全量巡检
- 一旦检查失败，应立即停下并向用户汇报风险

## 必须遵守的规则

1. **先检查，再执行重操作**：不要在没验证连通性之前直接导出、批量写入或大规模调用。
2. **优先最小探测**：先调元数据、列表、轻量读取接口，不要一上来就跑大查询。
3. **同时检查目标可达性**：MCP 服务正常不代表目标文件、页面、节点、文档一定存在。
4. **失败立即止损**：发现认证错误、服务错误、资源缺失时，不要盲重试。
5. **不要私自修配置**：涉及登录、授权、服务切换、环境配置变更时，只给建议，不自行改动。

## 执行步骤

### 1. 明确本次任务依赖的 MCP

从用户请求中识别当前真正相关的服务，例如：

- 设计类：Ardot、Figma
- 代码托管类：GitHub、GitLab
- 文档类：iWiki、Notion
- 数据类：Supabase、内部知识库、其他平台

如果用户明确点名了某个 MCP，只检查那个；如果任务涉及多个系统，只检查必要链路。

### 2. 进行轻量连通性探测

优先调用该 MCP 的轻量接口，例如：

- 列表接口
- 当前文件/页面信息
- 元数据读取
- 轻量搜索

目标是确认：

- MCP 工具可调用
- 响应结构正常
- 当前会话具备所需访问权限

### 3. 检查目标资源是否存在

结合本次任务，进一步确认目标资源可达：

- 目标文件 / 页面 / 节点 ID 是否有效
- 目标仓库 / 文档 / 数据集是否存在
- 本地目标路径是否存在且可读

如果任务需要“读远端 → 写本地”，要同时确认两端都可用。

### 4. 问题处置协议

一旦任一检查失败，立即停下，并按以下结构简洁汇报：

```text
⚠️ Preflight 未通过，建议暂停执行

- 问题：<具体错误>
- 影响：<为什么现在继续会不可靠>
- 建议：<1-3 条可执行建议>
```

在用户明确要求继续前，不要开始正式执行任务。

### 5. 检查通过后的输出

用简洁方式确认可继续，例如：

```text
✅ Preflight 通过
- MCP：<服务名> 可连通
- 目标：<文件/页面/资源> 可达
- 可以开始：<原任务>
```

## 反模式

- 发现报错后不停重复同一调用
- 没确认目标资源存在就开始生成内容
- 在 preflight 阶段偷偷改配置、换协议、换账号
- 把“检查”做成一次完整业务执行

## 与其他 skill 的关系

- 在设计落码、知识库检索、远端文档写入、MCP 导出等任务前先运行本 skill
- 检查通过后，再交给对应领域 skill 或实施流程继续执行
